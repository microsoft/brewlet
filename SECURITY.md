# Security

Microsoft takes the security of our software products and services seriously,
which includes all source code repositories managed through our GitHub
organizations.

If you believe you have found a security vulnerability in any Microsoft-owned
repository that meets
[Microsoft's definition of a security vulnerability](https://aka.ms/security.md/definition),
please report it as described below.

## Reporting security issues

**Please do not report security vulnerabilities through public GitHub issues.**

Report them to the Microsoft Security Response Center (MSRC) at
<https://aka.ms/security.md/msrc/create-report>.

You should receive a response within 24 hours. If you do not, follow up using
the messaging functionality at the bottom of the Activity tab in your
[vulnerability report](https://msrc.microsoft.com/report/vulnerability/) or use
the contact instructions on the
[MSRC report page](https://aka.ms/security.md/msrc/create-report). Additional
information is available from [MSRC](https://www.microsoft.com/msrc) and its
[reporting FAQ](https://www.microsoft.com/en-us/msrc/faqs-report-an-issue).

Include as much of the following information as possible:

- Type of issue, such as buffer overflow, injection, or privilege escalation.
- Full paths of source files related to the issue.
- The affected tag, branch, commit, or direct URL.
- Any special configuration required to reproduce the issue.
- Step-by-step reproduction instructions.
- Proof-of-concept or exploit code, if possible.
- The impact and how an attacker might exploit the issue.

For bug bounty submissions, complete reports can contribute to a higher award.
See the [Microsoft Bug Bounty Program](https://aka.ms/security.md/msrc/bounty)
for active programs.

## Preferred language

We prefer all communications to be in English.

## Policy

Microsoft follows
[Coordinated Vulnerability Disclosure](https://aka.ms/security.md/cvd).
