2. Watch nodes become ready:

     kubectl get nodes -L brewlet.sh/runtime

3. Deploy a runnable OCI image — use the full digest reported when publishing
   your application (replace the placeholder below), and route it with
   runtimeClassName: brewlet. Request a JDK installed on your ready nodes:

     metadata:
       annotations:
         brewlet.sh/jdk: "21"        # or "temurin-21"; matched against ready nodes
         # brewlet.sh/launcher: "jaz"  # only if explicitly installed
     spec:
       runtimeClassName: brewlet
       containers:
         - image: registry.example.com/demo/hello@sha256:<64-lowercase-hex>

   See https://brewlet.sh/docs/deploying-workloads/ for the image publishing
   and deployment steps. Example manifests must be configured before applying.

   …or let the operator do the wiring — apply a JavaApplication descriptor and it
   reconciles the Deployment + Service + HPA for you
   (see https://github.com/microsoft/brewlet/tree/main/specs):

     kubectl apply -f my-javaapplication.yaml
     kubectl get javaapplication -A

Uninstall safely:
  Drain Brewlet workloads and pause profile/GitOps writers first.
  The pre-delete hook waits for profile cleanup before removing the operator.
  Manually managed/other-release profiles and failed cleanup block uninstall.
  Do not bypass hooks or finalizers; the component namespace is retained.

    helm uninstall {{ .Release.Name }} --namespace {{ .Release.Namespace }} --timeout {{ add (int64 .Values.uninstall.timeoutSeconds) 60 }}s
