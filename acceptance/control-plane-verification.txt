Implemented production paths
----------------------------
API: github.com/microsoft/brewlet/kubernetes/api/v2alpha1
RuntimeImage, NodeProfile and immutable NodeRetirementEvidence are registered,
all cluster-scoped. There is no workload CRD or Java-specific controller.
RuntimeImage UID is the epoch. Status includes monotonic generation, approved
source/digest and immutable approved user/compatibility snapshots. A UID-bound
metadata write-ahead journal survives lost/pruned status and interrupted ABA
rotations; its allocation is CAS-written/read back before publishing status.
Unsupported/unverifiable recovery revokes approval rather than synthesizing
authority. Metadata/finalizer updates are CAS patches, not whole-spec rewrites.
Omitted/empty runtime compatibility is canonicalized by the CEL schema;
changing actual ecosystem/ABI identity is still forbidden.

Shared policy: github.com/microsoft/brewlet/kubernetes/policy
Source, Runtime, Profile, MirrorPolicy, Approved and ValidID are shared with
workers. Source references are normalized canonical tagless SHA-256 references.

Worker authority: github.com/microsoft/brewlet/pkg/control
Check(ctx, uncachedReader, Authority) returns Snapshot{Node,Profile,Spec,Target}.
Authority contains NodeName/UID, ProfileName/UID, Generation, immutable
TargetUIDs, Mode=provisioning|cleanup. Check requires the fresh Node claim and
durable matching profile ledger. Check never grants cleanup from a name alone.
Withdraw uses worker authority. WithdrawAdvertisement is controller-only
scheduling revocation that remains possible after invalidating spec edits.
Both use resourceVersion CAS and fresh UID/claim checks; provider Forbidden or
Invalid label refusal may fall back to a startup taint only after readback.
ReleaseClaim requires a durable Teardown checkpoint, no DaemonSets or Pods,
no remaining capabilities/inventory, and a fresh resourceVersion CAS.
StartupFenced confirms the exact key/value=provisioning/NoSchedule fence;
HasStartupTaint conservatively detects any same-key NoSchedule observation.
Fallback normalizes a nonstandard taint value before confirming scheduling safety.

Workers use /brewlet-node and literal BREWLET_PROFILE_NAME,
BREWLET_PROFILE_UID, BREWLET_PROFILE_GENERATION, BREWLET_TARGET_UIDS (JSON UID
array), BREWLET_MODE, BREWLET_PROFILE_SPEC, SOURCE_ALLOWED_MIRROR_HOSTS (JSON
array), and NODE_NAME from spec.nodeName. Worker freezes the actual Node UID
after checking the immutable target set. Host mounts are / -> /host,
/var/lib/containerd -> /var/lib/containerd, /run/containerd -> /run/containerd.
The worker has hostPID/hostNetwork and explicit profile tolerations only.
Cleanup completion marker is brewlet.sh/cleanup-complete=<profileUID>/<generation>.
Its readiness probe executes /brewlet-node --health-check, observing the genuine
pod-local /run/brewlet/ready completion gate maintained by the node worker.

Managers: kubernetes/cmd/operator and kubernetes/cmd/admission.
Operator supports --cleanup-coordinator with bounded exact-release uninstall.
Helm chart supplies TLS, admission, namespace-scoped worker mutation RBAC,
read-only global worker inventory, node-worker RBAC, pre-delete coordinator,
retained RuntimeClass and CRDs. Restart workload mutation RBAC is absent by
default, enabled only with operator.rotationRestarts.enabled. Root workload
opt-in is independently required. A separate kube-system election lease
serializes restart engines cluster-wide without changing the manager's existing
component-namespace lease during a rolling feature enablement. Cancellation of
global leadership cancels in-flight restart API operations.

Normal approval persists status.revocationTargets BEFORE node authorization,
with Node/profile UIDs, policy generation, physical identity, and the exact
generation/digest grant ceiling. This ledger survives removal of an entry from
a profile while old tasks still retain leases. Reauthorization reopens the
obligation; the node worker clears a stale positive receipt before minting it.
Profile teardown/receipt consumption cannot discard historical authority until
the inventory's independent resolution is durably observed.
Inventory deletion consumes the
node workstream's pkg/node.RevocationReceipt directly, never a parallel format.
Exact epoch/known-generation/digest/Node/profile/current-authority checks, RootsCleaned,
atomic-revocation timestamp, confirmed scheduling withdrawal/fence and separate
completion readback precede finalizer release. Missing/replaced original Nodes
need retained resolved external evidence, not absence or expiry alone.
A proven retired target keeps its last-granted ceiling when the image rotates
elsewhere; cleanup never replays outside frozen Teardown authority just to
acknowledge a newer, never-authorized generation.

Missing-host retirement copies each frozen obligation before removing active
membership, after old workers terminate. Administrative immutable evidence then
uses four separate checkpoints: retained finalizer, accepted external disposition
and cleanup snapshot, UID-bound receipt in the profile, resolved evidence.
Only then is the detached obligation consumed. Resolved evidence survives the
profile with no owner references. Node UID/providerID/systemUUID conflicts are
fenced without adopting claims, including the pre-detachment race window.
Old/unbounded workers, original still-present Nodes, legacy identities without
explicit mappings, foreign/recreated receipts and pruned snapshots block release.

Profile status reports assignedNodes/readyNodes, EmptyPool, AllNodesProvisioned,
NodeFailure and independent RetirementPending. Owned-node state is mirrored with
fresh fences and Provisioning/NodeReady/ProvisionFailed events. Optional
metrics.enabled exposes controller rotation/restart/profile gauges and enables
the genuine node metrics endpoint; collection errors fail scrapes explicitly.

Boundaries / remaining integration evidence (not success claims)
---------------------------------------------------------------
1. Actual host activation, authorization/root receipts, mount/lease inspection,
   recovery, collection, task execution and node metrics are node-workstream
   production paths. This controller trusts genuine fenced worker receipts;
   fake API tests cannot establish real host cleanup or task drain.
2. Arbitrary nonstandard containerd root/state paths are not modeled by the
   worker template, which explicitly mounts /var/lib/containerd and
   /run/containerd. Unsupported host layouts must fail worker validation.
3. Real scheduling behind provider-pinned labels, all-ID recovery, on-demand pin
   refusal, generation barriers, StatefulSet storage/partition behavior and
   actual lease preservation require the parent's isolated-cluster validation.
   No API/controller test is presented as runc/provider scale-from-zero proof.
4. Controller observations identify workload/Pod blockers; actual running-task
   epoch/generation comes from genuine node bindings/events/metrics, never from
   inferred Pod start time or an assumed successful template patch.
5. Automatic autoscaler scale-in/consolidation coordination is deliberately not
   supplied by the retained contract. Planned shrink must finish fenced
   cleanup/teardown before deleting the original Node/VM, or retain an explicit
   external-retirement obligation and administrative disposition.
