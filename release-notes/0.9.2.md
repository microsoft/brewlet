Brewlet 0.9.2 is a patch release on the 0.9.x line.

- **Mixed containerd plugin layouts:** some containerd 2.x nodes (for example
  AKS Ubuntu 24.04 with containerd 2.3) keep `version = 2` on disk while
  already declaring the split `io.containerd.cri.v1.runtime` and
  `io.containerd.cri.v1.images` tables. 0.9.1 wrote the Brewlet runtime
  handler into the legacy `io.containerd.grpc.v1.cri` table, which containerd
  ignores during migration, so activation failed with `brewlet handler or
  required pod_annotations forwarding missing`. The node provisioner now
  writes into the existing split tables, preserves runc options and rejects
  unmanaged Brewlet handlers in either table.
- **Recovery from blocked teardown:** fenced cleanup now removes offered,
  historical and authorized runtime IDs backed by genuine revocation
  receipts, and the operator resolves released inventory targets so a
  NodeProfile stuck in teardown after a failed activation can finish.
- **Evidence collection after shim removal:** the node provisioner falls back
  to its trusted bundled evidence collector when the host shim has already
  been removed.

Nodes that failed to activate on 0.9.1 with the error above become ready after
upgrading to 0.9.2; no manual host changes are required.
