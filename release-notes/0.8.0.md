> [!IMPORTANT]
> **Brewlet 0.8.0 pivots to a language-agnostic runtime governance model.**
> Brewlet now moves language runtimes into infrastructure: platform teams
> approve and rotate digest-pinned runtimes per node pool, and applications
> ship as standard OCI artifacts for Java, Python, Node.js and .NET alike. It
> still does most of what the previous Java-specific line did (0.7.x and
> earlier, now tracked in the
> [`brewlet-0.x-java`](https://github.com/microsoft/brewlet/tree/brewlet-0.x-java)
> branch), just no longer Java specific. There is no in-place upgrade from
> 0.7.x; re-author workloads for the new model.
>
> Read [Brewlet 0.x vs. 1.0.0: capabilities and equivalent workflows](https://github.com/microsoft/brewlet/blob/a594785a8d278a55c8ace585a4d65df23f62f25e/docs/legacy-comparison.md)
> to see how existing 0.x workflows map to this release.

> [!WARNING]
> **0.x releases are not stable.** Every 0.x version is a beta: APIs, artifact
> formats, CRDs and behavior can break, change incompatibly or pivot again
> between releases. Do not use 0.x in production. General availability (GA)
> will be **Brewlet 1.0.0**.
